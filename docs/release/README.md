# Выпуск WindowZones 0.1

История первого выпуска: 0.1.0 опубликован 19 сентября 2026. Подпись, notarization и Sparkle upgrade подтверждены в tasks/13-distribution.md. Порядок подготовки 0.2.0 описан в ColleaguePreview.md; каждый новый архив проверяется отдельно.

## Что делает CI

`checks.yml` запускает тесты и собирает ad hoc приложение для проверки. Оно не является релизом.

`release.yml` запускается вручную из main, получает существующий tag и номер сборки. Проверяет принадлежность tag истории main и рост номера относительно всех опубликованных выпусков. Затем импортирует временный Keychain, собирает arm64 приложение, подписывает вложенные компоненты Sparkle и приложение, отправляет архив Apple, требует статус Accepted, прикрепляет ticket, проверяет Gatekeeper. Только после этого создаёт ZIP для пользователей, EdDSA подпись и appcast, затем draft release на GitHub.

Workflow не публикует draft. Это позволяет проверить конкретный подписанный артефакт перед выпуском. Файлы после EdDSA подписи нельзя перепаковывать или менять. Обновления использует штатный Sparkle 2.10.0, самописного установщика нет.

## Настройка GitHub

Репозиторий: `shumer/WindowZones`. Environment: `release`, как в FinderExtension. Настройка environment и перенос ключей не выполняются этими файлами автоматически.

Secrets:

- `DEVELOPER_ID_P12`: base64 экспортированного Developer ID Application сертификата вместе с приватным ключом.
- `DEVELOPER_ID_P12_PASSWORD`: пароль экспорта.
- `NOTARY_KEY_P8`: base64 App Store Connect API приватного ключа.
- `NOTARY_KEY_ID`, `NOTARY_ISSUER_ID`: идентификаторы API ключа и issuer.
- `SPARKLE_PRIVATE_KEY`: приватный EdDSA ключ Sparkle в base64. Предпочтительна отдельная пара WindowZones; использование ключа другой утилиты допускается как явное решение владельца.

Variables:

- `BUNDLE_ID`: постоянный публичный bundle identifier, без `local.`. Выбрать до первой установки релиза и больше не менять.
- `SPARKLE_PUBLIC_KEY`: необязательное закрепление публичного EdDSA ключа. Если задано, несовпадение останавливает сборку. Если отсутствует, CI получает публичный ключ из приватного и проверяет пробную подпись штатным Sparkle.

Ключи не хранить в репозитории, документации или логах. Подготовить пару штатным `generate_keys` из Sparkle. Скрипт `check-update-key.swift` понимает seed из 32 байт и legacy export из 96 байт, проверяет подпись случайного сообщения через `sign_update` и CryptoKit. Только публичный ключ передаётся в сборку. Приватный ключ передаётся `sign_update` через stdin, не импортируется в пользовательский Keychain и не сохраняется в файл. Временный CI Keychain для Developer ID и notarization удаляется в завершающем шаге, включая ошибки.

## Версии SDK и оборудования

Минимальная ОС приложения: macOS 15.0. Релиз 0.1 собирается только для Apple silicon. Intel не поддерживается этим артефактом.

Локальная разработка использует CLT Swift 6.4 / SDK 27.0. Для GitHub выбран документированный `macos-26` arm64 runner, `/Applications/Xcode_26.6.app/Contents/Developer`, SDK 26.5. В workflow задан `EXPECTED_SDK=26.5`, поэтому исчезновение этой версии останавливает сборку. Автоматического перехода на новый Xcode нет. Это отдельная конфигурация, её совместимость должна быть подтверждена первым прогоном CI. Наличие runner в документации не означает, что проект уже собран на нём.

## Первый кандидат

1. Убедиться, что checks прошёл и release environment заполнен.
2. Зафиксировать код в main и создать tag `v0.1.0` на проверенном коммите.
3. В Actions запустить Signed release candidate из main, tag `v0.1.0`, build_number `1`.
4. Проверить notarization evidence и скачать ZIP из draft. Для private репозитория публичный appcast недоступен: публичный HTTPS хостинг или public репозиторий нужны до выпуска.
5. Распаковать и перенести WindowZones.app в `/Applications`. На отдельном чистом пользовательском профиле проверить Gatekeeper, начальную выдачу Accessibility, запуск, автозапуск после повторного входа, выключение автозапуска, основные размещения и Undo.
6. Собрать второй кандидат с большим build number для реального обновления первого. Проверить загрузку, верификацию, установку, перезапуск, сохранение настроек и разрешения Accessibility, отказ при повреждённом архиве и недоступной сети. Временный тестовый feed не публиковать как основной.
7. После этих проверок опубликовать проверенный draft отдельным действием. Текущий feed рассчитан на обычный release, не prerelease: `https://github.com/shumer/WindowZones/releases/latest/download/appcast.xml`.

Не менять bundle ID, Developer ID team, EdDSA ключ или конечный feed между кандидатами без отдельного плана миграции. Подпись сертификатом помогает стабильности идентичности приложения, но сохранение Accessibility после обновления всё равно проверяется практически.

## Последующие обновления

Новая версия и новый tag, строго больший build number. Пример: `v0.1.1`, build `2`. Выполнить тот же workflow. Draft не изменяет latest feed. Публикация нового обычного release делает его appcast доступным по постоянному URL. Этот простой feed содержит только последний полный ZIP, без delta updates и автоматического отката. Для экстренного исправления выпустить новый build, не понижать номер.

## Проверено и ещё не проверено

Для 0.1.0 подтверждены Developer ID, CI на закреплённом SDK, notarization и Sparkle upgrade тестовой 0.0.0. Чистая установка и полный диапазон macOS остаются непроверенными. Эти результаты не заменяют проверку нового архива.

Источники: [Sparkle manual signing](https://sparkle-project.org/documentation/sandboxing/), [Sparkle publishing](https://sparkle-project.org/documentation/publishing/), [GitHub macOS arm64 image](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md). Проверены 19 сентября 2026.

## Ключ WindowZones

Для WindowZones создан отдельный ключ Sparkle в локальной связке ключей, account `com.shumer.WindowZones`. Приватный ключ хранится также в GitHub environment release, secret SPARKLE_PRIVATE_KEY. Не заменять ключ при обычном выпуске. Публичный ключ включён в Resources/Info.plist; CI дополнительно проверяет соответствие секрету.

## Локальное обновление установленного приложения

С 7 октября 2026 использовать только `./scripts/install.sh`, для проверки UI `./scripts/install.sh --diagnostics`. Скрипт запускает тесты, build.sh и sign-app.sh, выбирает Developer ID команды MW9955TT6R, проверяет bundle ID и подпись до замены. `SKIP_TESTS=1` разрешён, когда тесты для текущих изменений уже прошли. Первую установку в Applications выполняет пользователь.

Разрешение App Management у приложения, запускающего скрипт, нужно независимо от sandbox. При отказе записи скрипт останавливается до удаления содержимого. Не обходить отказ через Finder или sudo. После успешной проверки запись идёт только в /Applications/WindowZones.app; предыдущая копия сохраняется в .build/install-backup/WindowZones.app. Скрипт не публикует релиз и не нотарифицирует локальный кандидат.

Постоянная подпись нужна для сохранения Accessibility; после установки проверять фактический статус и размещение окна. При сбросе разрешения сообщать пользователю, не выдавать его заново автоматически. Правила не означают, что смена сертификата при продлении гарантированно сохранит каждое разрешение macOS.

Проверка 7 октября: первый `./scripts/install.sh --diagnostics` и повторный `SKIP_TESTS=1 ./scripts/install.sh --diagnostics` завершились строкой Installed с team MW9955TT6R. Первый прогон включал 45 успешных тестов. После повторной установки диагностика показала Accessibility разрешён, реальный Finder snap из 1284/38/1268/1304 в 8/38/1268/1304 завершился exact за 227 ms. Повторного запроса разрешения не было. build.sh и sign-app.sh не менялись.


## Установка готового релизного кандидата

Использовать `./scripts/install.sh --release-app /absolute/path/WindowZones.app --diagnostics`. Этот режим не пересобирает и не переподписывает архив. До замены Applications он требует codesign, stapler и Gatekeeper, затем проверяет постоянные team ID и bundle ID. Остальные проверки App Management и сохранение резервной копии остаются общими с обычной установкой.

Prerelease на GitHub не заменяет latest и не поступает в стабильный Sparkle feed. 0.2.0 по последующему запросу пользователя опубликована обычным release и доступна в latest feed. Проверена ручная замена приложения; автоматический upgrade до неё не заявляется проверенным.
