# Проверка понятности WindowZones

Статус: протокол подготовлен. Участники не приглашались, сессии не проведены. Вымышленных результатов нет.

## Подготовка

3-5 участников с опытом Mac, часть с опытом Windows/FancyZones. Зафиксировать мышь или трекпад, размер экрана, опыт управления окнами. Начать с работающего ProductReview.html, не с template. На реальном Mac отдельно проверить системный tiling и хотя бы одного конкурента. Запись экрана только с согласия участника, без личных документов.

Сначала нейтрально сказать: «Эта утилита размещает выбранное окно в вашей раскладке». Не объяснять зоны и расположение кнопок заранее. A и B показывать в разном порядке разным участникам. B пока концепт, а не работающая интеграция с titlebar.

## Задания

1. Поместить окно в широкую центральную область.
2. Выбрать другую раскладку. До клика спросить, какие окна, по ожиданию участника, изменятся.
3. Отменить ошибочное размещение.
4. Создать 25/50/25, разделить правую колонку и сохранить. Учесть, что макет показывает только часть будущего редактора.
5. Изменить пропорцию и отказаться от изменения.
6. Найти настройку разрешения и понять, зачем оно требуется.
7. Обсудить перенос на другой монитор по сценарию: текущий макет с одним экраном не проверяет этот flow.

Для Shift-drag нужна отдельная нативная сессия. Макет не является проверкой mouse-up, отмены Shift или ложных жестов.

|---|---|---|---|---|---|---|
| Не проведено | | | | | | |

Сравнивать обнаружение входа, точность выбора, понимание смены раскладки и отмены. Не выводить статистическую достоверность из 3-5 сессий. Кандидат условия итерации: из пяти участников четверо выполняют размещение и отмену после короткого знакомства; каждый случай ошибки разобран.

Итог сессий: выявленные проблемы, изменения макета, решение A/B, открытые вопросы, следующий тест. Внешние контакты и отправка материалов требуют отдельного поручения пользователя.
