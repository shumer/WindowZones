# Контракт локального хранения

Задача 05. Независимый модуль LayoutStorage зависит только от Geometry и Foundation. Подключён к executable WindowZones в задаче 06. Сам модуль не вызывает AX и не перемещает окна.

## API

- LayoutCollection: раскладки и словарь activeByDisplay. Ключ экрана пока непрозрачная строка; устойчивое определение идентичности монитора относится к задаче 09.
- committingPlacement(layoutID:displayKey:succeeded:): возвращает новую коллекцию только при успешном размещении. При false возвращает исходную без смены active layout. Нативный AppController вызывает его после успешного AX read-back в задаче 06.
- LayoutArchive.encode/decode: экспорт и импорт Data с проверкой версии и ограничений. Импорт возвращает данные и ничего не пишет.
- LayoutStore(directory:): actor с сериализованными load/save. Инициализация не создаёт каталог или файлы.
- applicationSupportDirectory(): путь Application Support/WindowZones без создания каталога. В этой задаче туда ничего не записывалось.

## Схема 1

Верхний уровень JSON содержит schemaVersion: 1, layouts и activeByDisplay. Каждая раскладка содержит id, name, inset, gap и плоский массив nodes. Первый элемент массива является корнем.

Узел zone: kind, id, name. Узел split: kind, axis (vertical/horizontal), ratio, first и second, последние два являются индексами детей в массиве. Отсутствующие обязательные поля и несовместимые поля другого kind отвергаются. Неизвестный kind и axis не угадываются.

Плоское представление ограничивает построение рекурсивного дерева: максимум 23 узла для 12 leaf, глубина максимум 12. Цикл, повторное использование одного ребёнка, неверный индекс и недостижимый узел считаются повреждением документа. После сборки дерева выполняется доменная валидация ratio, spacing, leaf IDs и ссылок активных раскладок.

UUID раскладок уникальны внутри коллекции; UUID зон уникальны внутри раскладки. Коллекция не пустая. activeByDisplay не допускает пустой ключ и ссылку на отсутствующую раскладку. Имена сохраняются с Unicode, без превращения в имена файлов.

Предельный размер архива: 1 048 576 bytes. Файл читается порциями не больше 65 536 bytes, с общим пределом limit + 1 для обнаружения превышения. JSON декодируется только после проверки лимита. Схемы, отличные от 1, дают unsupportedVersion; миграций из ранее выпущенных схем нет, потому что это первая схема.

## Файлы и восстановление

Рабочий файл layouts.json, резервный layouts.backup.json.

load сначала пробует рабочий файл. При повреждении и доступной валидной резервной копии возвращает её с source=backup. Он не переписывает рабочий файл автоматически. Если оба повреждены, возвращает ошибку. Встроенные шаблоны с source=defaults возвращаются только если оба файла отсутствуют.

Неизвестная версия рабочего файла не маскируется старым backup. save также отказывается изменять файлы, если рабочий или резервный файл содержит неизвестную версию. Это защищает данные после запуска более старой сборки приложения.

save сначала полностью кодирует и проверяет новую коллекцию. При валидном предыдущем рабочем файле он атомарно сохраняется как backup, затем новая версия атомарно записывается как primary. Повреждённый primary не заменяет валидный backup. Повреждённый backup можно восстановить из валидного primary.

На первом сохранении появляется только primary, резервная предыдущая версия появляется при следующем успешном сохранении. Операции над двумя файлами не являются одной файловой транзакцией. Порядок записи сохраняет валидную копию при ошибке между шагами; абсолютная гарантия против сбоя накопителя или потери питания не заявляется. При ошибке вызывающая сторона должна сообщить о ней и перечитать состояние, не утверждая, что сохранение завершилось.

Сериализация actor действует в одном процессе. Одновременная запись разными процессами не поддерживается этим контрактом. Механизм единственного экземпляра приложения при необходимости проверяется при интеграции.

## Проверки и границы

13 тестов хранения: round-trip, Unicode, размер, версия, UUID и active references, смена active только после успеха, отсутствие записи при первом load, предыдущая резервная версия, повреждённый primary, повреждённые оба файла, защита файлов от невалидного сохранения, новая схема backup, циклы/общие дети/неверные ссылки и посторонний недописанный temp.

Полный прогон проекта: 42 теста, из них 29 геометрии и 13 хранения. Всё прошло. Сценарий с недописанным temp является моделью оставшегося файла, не реальной имитацией отключения питания во время системного rename. Все тестовые записи выполнялись в собственных временных папках и очищались тестами. Работа с настоящими профилями мониторов, onboarding, UI импорта и восстановление при запуске приложения относятся к последующим задачам.

Интеграция 06 использует публичный [ColorSync CGDisplayCreateUUIDFromDisplayID](https://developer.apple.com/documentation/colorsync/cgdisplaycreateuuidfromdisplayid(_:)) для ключа экрана. Отсутствующий или неоднозначный UUID не заменяется сохранением по имени или временному индексу. Проверка восстановления после физического переподключения остаётся в задаче 09.
