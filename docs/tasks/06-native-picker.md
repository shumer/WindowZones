# 06. Нативная панель и цельный сценарий

Статус: Реализация подключена, ручная приёмка впереди.
Зависимости: 02, 03, 05.

[Очередь задач](README.md) · [Спецификация](../Specification.md)

## Результат

Реализовать активное окно -> панель -> preview -> размещение -> undo в нативном приложении.

## Работа

- [ ] Сохранить target до показа панели. Четыре миниатюры, доступные зоны, указание приложения и монитора.
- [ ] Hover/focus только preview; click/Enter применяет, Escape/клик снаружи отменяет.
- [ ] Tab, стрелки, 1-9; доступ к зонам 10-12. Не перехватывать Command+Z.
- [ ] Read-back определяет успех; active layout меняется только при успешном результате.
- [ ] Сохранять target при смене фокуса панели; закрытый target не заменять другим окном.

## Проверки и условие завершения

- [ ] На Mac пройдены мышь, клавиатура, отмена, потеря target и возврат focus.
- [ ] Панель не становится целевым окном, прочие окна не переставляются.
- [ ] Полный сценарий доступен без окна диагностики.

## Границы

Без кнопки поверх titlebar и Snap Assist.

### 2026-09-19: четыре раскладки и хранение

По поручению пользователя продолжить подключены четыре раскладки из библиотеки в сетке 2x2. Это дальнейшая реализация 06 до завершения ручной приёмки 02/03 по решению продолжать работу; карточка остаётся открытой.

- Миниатюры, overlay и применение используют LayoutGeometry выбранного монитора. Слишком маленькая раскладка отключается. Кнопки соответствуют листьям, включая верхнюю и нижнюю зоны правой колонки.
- Загрузка LayoutStore выполняется без перемещения окон и без записи при запуске. Команда выбора ждёт завершения загрузки. Повреждённое или неизвестное хранилище не перезаписывается через fallback.
- Наведение, Escape, переключение монитора и неудачный AX не сохраняют выбор. После успешного read-back сохраняется activeByDisplay. При ошибке записи выбранный вариант остаётся на текущий сеанс с сообщением о несохранённом выборе.
- Ключ экрана получается публичным ColorSync CGDisplayCreateUUIDFromDisplayID, доступным начиная с macOS 10.4. При отсутствующем или неоднозначном UUID постоянное сохранение пропускается. Полная проверка reconnect и одинаковых мониторов остаётся задачей 09.
- Цифры 1-9 учитывают количество зон, стрелки и Tab дают доступ ко всем. Стрелки синхронизируют selection и first responder; Enter/Space на кнопке применяют её зону. Модифицированные сочетания передаются дальше.
- Клик любой кнопкой мыши в другом приложении закрывает picker без возврата фокуса. Escape отменяет. Перед активацией target повторно проверяется token отмены.
- Shift-drag подключён к той же активной геометрии, чтобы после выбора другой раскладки не показывать прежние три зоны. Это начальная интеграция 07, а не подтверждение надёжности жестов.

Read-only ревью отдельным агентом нашло и помогло исправить фиксированный canvas миниатюр, несовпадение клавиатурного фокуса и выбора, позднюю активацию отменённого target и отсутствие отмены правым кликом. Изменения требуют проверки физической клавиатурой и реальным AX.

На реальном Mac через UI проверен статус прежней сборки: Accessibility не разрешён. Новые AX snap/undo и keyboard сценарии не проводились. Старый процесс остановлен перед обновлением bundle.

Итог продолжения: release собран и подпись проверена. Обновлённое приложение запущено через UI, диагностика доступна, Control+Option+Space зарегистрирован, обнаружены три экрана. Accessibility остаётся не разрешён. Все 42 теста проходят. Финальные PNG обеих тем просмотрены. Живая проверка AX остаётся непроведённой; карточка не закрыта.

### Проверка после выдачи Accessibility

Пользователь сообщил, что выдал доступ. Через UI нажата «Обновить статус»: приложение подтвердило «Accessibility: разрешён». На запуске доступны три экрана с масштабами 1/2/1. Создано отдельное окно Finder в папке проекта для проверок.

Две попытки отправить Control+Option+Space через CUA не открыли панель. Это наблюдение об автоматическом вводе, а не доказательство отказа физического shortcut. Запрошено одно физическое нажатие пользователем. До первого успешного размещения каталог Application Support/WindowZones отсутствует, что соответствует отсутствию записи при запуске.

Пользователь подтвердил открытие панели физическим Control+Option+Space. Диагностика содержит получение shortcut и захват com.apple.finder. CUA при этом выбирал окно диагностики, а не picker; отправка цифры 2 через CUA не дала подтверждённого результата. Диагностика закрыта для повторного подключения непосредственно к панели. Эти действия пока не считаются успешным размещением.

### Первый реальный прогон новой панели

После закрытия диагностики CUA получил дерево настоящего picker для Finder на экране 3 (2560x1410, scale 1). Проверено:

- В UI доступны четыре раскладки, включая отдельные кнопки верхней и нижней правой зоны.
- Нажатие Right перевело выбор с зоны 2 на зону 3 «Широкого центра». AX focused element также перешёл на кнопку зоны 3, а не остался на предыдущей.
- Клик на зону 2 раскладки «Пополам» закрыл picker. Finder получил высокое окно правой половины, визуально подтверждённое снимком CUA.
- Появился layouts.json, schemaVersion=1, 4 layouts. Для UUID целевого монитора сохранена раскладка «Пополам». До команды файл отсутствовал. Точные AX frame и timing пока не извлечены; визуальное совпадение не выдаётся за измерение допуска.

Для read-back отчёта и undo запрошено открытие диагностики пользователем, поскольку CUA не получает status item без обычного окна. Release не пересобирался и разрешение не сбрасывалось.

Диагностика открыта пользователем. Прочитан результат snap: adjusted 563 ms, y +16 pt, height -8 pt. Выполнен Undo кнопкой диагностики: adjusted 576 ms, исходный размер восстановлен, y -9 pt. Хранилище после undo не изменилось. Подробные frames внесены в Stage0Results.md. Приёмка точного размещения не пройдена.

В WindowAccess подготовлена одна завершающая коррекция позиции после size с объединением keepVisible. Прямое наблюдение не доказывает, что система примет повторную позицию; реальный повтор обязателен. App bundle с текущим Accessibility пока не заменён. Следующий шаг: установить подготовленную сборку в рамках следующего реального прогона, при необходимости повторно разрешить доступ, повторить этот же Finder snap/undo и затем остальную матрицу.

### Диагностический вход без физического shortcut

По запросу пользователя добавлены список запущенных приложений, обновление списка и кнопка «Открыть выбор зон». Команда сохраняет PID явно выбранного приложения и использует общий beginPicker/capture. Никакого выбора произвольного окна при запуске и автоматического размещения нет.

При таком входе диагностика скрывается перед панелью и возвращается без активации после выбора или обычной отмены. Отмена из-за Space/sleep не возвращает диагностику. Ошибка capture показывает существующее объяснение. Это инструмент проверки, основной shortcut и обычное меню остаются.

42 теста прошли; read-only ревью не нашло блокирующих ошибок. В сборку также входит подготовленная отмена rollback. Окно диагностики увеличено до 760x600 для новых controls. Реальная проверка нового входа фиксируется ниже после установки.

Новый вход установлен и проверен через CUA на реальном Mac: список доступен (Finder выбран), кнопка доступна и запускает capture именно com.apple.finder. После ожидаемого denied диагностика вернулась. Accessibility новой ad hoc сборки сброшен; открыт раздел настроек. Успешное открытие picker новым входом до повторной выдачи доступа не проверено. Ни окна, ни архив при denied не изменялись командой размещения.

Диагностический вход после выдачи доступа подтверждён реальным открытием picker, snap, Undo и Escape без помощи пользователя. Проверены Finder scale1 (exact snap/undo) и scale2 (snap height -25 pt, exact undo). Final position correction реально исправила позицию на Retina. Остаются точность высоты и Tab из начального focus окна. Подробные frames и границы в Stage0Results.md. Автоматический доступ к Terminal отклонён политикой CUA, не обходить ограничение через другой интерфейс.

### Исправления после самостоятельного прогона

- Tab/Shift+Tab обрабатываются PickerWindow.sendEvent. Цепочка строится из видимых доступных controls и работает от исходного firstResponder=window независимо от системной настройки keyboard navigation. Popup, зоны и Cancel имеют явную фокусируемость. Return на popup не вызывает скрытый snap; Enter/Space на Cancel отменяют.
- Добавлен scripts/PickerKeyboardCheck.swift, in-process AppKit проверка без чужих окон: 12 зон, прямой/обратный проход, wrap, hidden/disabled, отсутствие snap при Tab, активация и отмена. Проверка прошла. Живой CUA-прогон новой сборки ещё впереди.
- WindowAccess теперь сначала только уменьшает размер по каждой оси, переносит окно и затем увеличивает до target. Это гипотеза устранения clipping у старой позиции; не подтверждённое исправление высоты. Максимум четыре записи сохранён, бюджет 900 ms и rollback 1500 ms без изменения. При нехватке бюджета финальная position может быть пропущена и результат останется adjusted.
- Перед записями после await повторяется validate. Допуск settle при входе поднят с 150 до 175 ms, учитывая первое обязательное ожидание проверки стабильности.
- Read-only ревью AX не нашло нового дефекта, но напомнило: старая последовательность rollback size->position сама может дать adjusted при частичной ошибке. Это не полноценная атомарность и не закрытый сценарий rollback.

Повторить на Mac исходный Retina Finder -1216/162/920/436 -> -1504/41/744/933 и Undo. Оценивать actual frame, а не только факт видимого изменения окна. Не обходить запрет CUA на Terminal.
