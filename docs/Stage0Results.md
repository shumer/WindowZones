# Этап 0: результаты и ручная проверка

Дата: 19 сентября 2026.

Статус: прототип собран и запущен, 10 unit tests прошли. Выполнено по одному циклу в пяти приложениях: Finder, Safari, Chrome и Slack попали в допуск 2 pt; Terminal дал +7 pt по высоте. Во всех пяти undo точно восстановил исходный frame. Этап 0 в целом ещё не завершён. Для завершения этапа нужны реальные snap/undo и drag-эксперименты. Наличие исходников не означает прохождение приёмки.

- Сборка локальная, ad hoc подпись `local.windowzones.stage0`. Нет Developer ID и notarization.
- Read-only probe вне песочницы: один экран, id 1, frame `(0, 0, 1512, 982)`, visibleFrame `(0, 52, 1512, 897)`, scale 2. Accessibility=false для диагностического executable. Внутри песочницы список экранов был пуст.

- Unit tests используют Swift Testing, доступный в этих Command Line Tools. XCTest в установленном toolchain отсутствует. Скрипт тестов явно подключает поставляемый `libTestingMacros.dylib`: стандартный запуск SwiftBuild не нашёл этот plugin автоматически.

## Сборка и запуск

Из корня проекта:

```sh
./scripts/test.sh
./scripts/build.sh
open build/WindowZones.app
```

Сборка создаёт `build/WindowZones.app`. Для повторного запуска закрыть предыдущую копию через меню приложения. Не запускать одновременно пакетный executable и app bundle: у них может отличаться разрешение Accessibility.

`scripts/swift.sh` хранит кеши в `.build`. Флаг `--disable-sandbox` отключает только дополнительную песочницу SwiftPM для локального package manifest. Он не отключает SIP, системные разрешения или защиту macOS. Первичная сборка с системным расположением кеша не прошла из-за запрета записи в `~/.cache/clang`; повторная использует локальный кеш. Генерация dSYM для release также была заблокирована песочницей; release проверяется локально вне неё.

## Реализация

- Menu-bar app и окно диагностики. Запуск только показывает диагностику, чужие окна не перемещает.
- Три фиксированные зоны 25/50/25 после вычета двух gaps. Отступы и gaps по 8 pt, минимальная сторона зоны 120 pt.
- Control+Option+Space захватывает focused AX window чужого активного приложения до показа picker. Нажать 1, 2 или 3, либо стрелки и Enter. Escape отменяет. Можно выбрать экран.
- При конфликте регистрации shortcut меню позволяет выбрать Control+Option+Space. Конфликты, которые macOS не сообщает через RegisterEventHotKey, требуют ручной проверки.
- Отсутствующий Accessibility возвращает denied. Кнопка открывает Settings только по нажатию, автоматического запроса разрешения нет. Статус обновляется при действиях и по кнопке.
- Проверяются роль, subrole, minimized, fullscreen и возможность менять position/size. Неизвестный fullscreen статус консервативно означает unsupported.
- AX сериализован отдельным actor, UI и event callback не ждут синхронно чужое приложение. До каждого AX-вызова проверяется отмена и оставшийся бюджет.
- Timeout до 250 ms на вызов. Snap получает 700 ms на проверки, запись size/position/size и отложенный read-back; оставшиеся до общего бюджета 1000 ms зарезервированы для восстановления при частичной ошибке. Это бюджет запроса, не гарантия точного времени завершения системного AX-вызова.
- Результаты exact, adjusted, unsupported, denied, failed. Точность exact: не более 2 pt по каждой компоненте. Нет бесконечных повторов AX-записи.
- Undo хранит живую AX reference, исходный frame до picker/drag, фактический результат и исходный экран. История только в памяти, один слот. После отключения исходного экрана frame ограничивается доступной рабочей областью.
- Диагностика содержит только геометрию, коды результата и время, без названий окон, документов и содержимого клавиатурных событий. Последние 30 записей в памяти.

## Эксперимент Shift-drag

Включается отдельно пунктом меню. Используются публичные NSEvent monitors. Event tap и запрос Input Monitoring не добавлены. По документации Apple мониторинг клавиатурных событий зависит от Accessibility; фактическую конфигурацию разрешений нужно проверить на этой сборке.

Кандидат захватывается на mouse-down даже без Shift, чтобы сохранить геометрию до переноса. Допускаются AXTitleBar либо AXWindow в узкой верхней полосе, с исключением краёв. Если начальная AX-проверка не успела до смещения курсора больше 3 pt, жест отвергается. Затем во время жеста проверяется движение того же AX-окна при неизменном размере и смещение, согласованное с курсором. Проверка не чаще одного одновременно выполняющегося AX-запроса; дополнительный timer 100 ms работает только при кандидате жеста.

Overlay не активируется и пропускает мышь. Escape, отпускание Shift после его первого нажатия, смена экранов/Spaces, сон, потеря Accessibility или недоступность окна отменяют жест. После отмены нужен новый mouse-down. Перед snap на mouse-up геометрия повторно проверяется.

Это консервативная эвристика. Она может пропускать быстрые переносы и нестандартные toolbar/titlebar. Нет подтверждения, что отрицательные сценарии и системный tiling проходят. Отсутствие overlay на конкретном приложении нужно записать как ограничение, а не считать успешной проверкой.

## Короткий сценарий первого прогона

1. Запустить app. В диагностике проверить Accessibility и shortcut. Через кнопку открыть настройки. Если WindowZones уже есть в списке, включить его переключатель; иначе вручную добавить `build/WindowZones.app` в Accessibility. После изменения вернуться и нажать «Обновить статус». Системный tiling не менять.
2. Активировать обычное окно Finder. Нажать Control+Option+Space, затем 2. Окно должно занять центральную зону. Открыть диагностику через значок меню и сравнить expected/actual.
3. Выбрать «Отменить последнее размещение». Проверить возврат к original. Повторить для зон 1 и 3, затем для Safari и Terminal. Полная приёмка: 10 snap/undo на каждое приложение.
4. Включить «Эксперимент Shift-drag». Зажать заголовок обычного окна, начать медленный перенос, удерживать Shift. Отпустить мышь внутри зоны. Undo должен вернуть frame до начала переноса.
5. Повторить жест с Escape и отдельно с отпусканием Shift до мыши. После mouse-up не должно быть snap. Затем перетащить текст, файл, вкладку и изменить размер окна: по 5 попыток каждого типа, без ложного snap.
6. Повторить на двух Chromium/Electron-приложениях из рабочего набора. Отдельно проверить минимальный размер, закрытие выбранного окна, fullscreen, minimized, отзыв Accessibility и перенос между экранами.

После ad hoc пересборки macOS может потребовать удалить старую запись Accessibility и добавить приложение снова. На этом Mac потеря доступа после пересборки подтверждена: новая сборка показывает false, предыдущая показывала true. Designated requirement ad hoc подписи зависит от cdhash. Это делает пользователь вручную; настройки TCC приложение не изменяет.

## Ход ручного прогона

- Пользователь выдал Accessibility локальному app bundle. Обновление статуса с false на true подтверждено в UI без перезапуска.
- Синтетическое Control+Shift+Space через инструмент UI не открыло picker. Физическое нажатие пользователем открыло picker и три зоны. Пользователь отметил, что непонятно, как убрать overlay. Escape через UI-инструмент закрыл picker.
- По этому замечанию добавлена явная кнопка «Отмена (Esc)», picker поднят над overlay, повторный shortcut отменяет выбор. Уменьшена заливка зон. Обновлённая release-сборка собрана, подпись проверена, приложение запущено; наличие кнопки undo в диагностике подтверждено через AX. Повторная проверка picker ожидается: после ad hoc пересборки Accessibility снова false, нужно повторное ручное разрешение.

### Сбой вызова picker в обновлённой сборке

После повторной выдачи Accessibility пользователь сообщил: физическое Control+Shift+Space не открывает picker. UI отвечает, Accessibility=true, регистрация shortcut отображается как успешная. Ранее успешный физический shortcut относится к предыдущей сборке и не подтверждает текущую.

### Проверка через меню и фактический read-back

Пользователь подтвердил, что команда через status menu открывает picker и зоны. В диагностике текущей сборки обнаружены три размещения. Идентификатор целевого приложения в этой версии диагностики отсутствует, поэтому эти операции нельзя уверенно засчитать как тест Finder.

| Операция | Original x/y/w/h | Expected x/y/w/h | Actual x/y/w/h | Результат |
|---|---|---|---|---|
| Центр | 58/33/1315/865 | 386/41/740/881 | 386/57/1315/865 | adjusted, 92 ms |
| Справа | 386/57/1315/865 | 1134/41/370/881 | 1134/48/1315/865 | adjusted, 212 ms |

Это не подтверждает точное возвращение в исходное положение; текущая проверка fallback слишком широкая и требует уточнения. Проверяется смена сочетания на Control+Option+Space без пересборки.

### Локализация сбоя и следующая сборка

- Пользователь подтвердил: после переключения на Control+Option+Space picker открывается. Сбой локализован до исходного сочетания/его доставки; конкретный перехватчик не установлен. Рабочее сочетание стало начальным для следующей сборки; Control+Shift+Space остаётся альтернативой в меню.
- Пользователь подтвердил, что четыре размещения с неизменным размером выполнялись на Finder. Это уточняет ранее неизвестное приложение в таблице.
- Обычный resize левого края через UI-инструмент уменьшил окно Finder, toolbar перестроился. Значит, ширина 1315 не является жёстким минимумом этого окна. Точный новый AX frame не измерялся.
- Подготовлена последовательность size/position/size, read-back спустя 80 ms и максимум одна корректировка position для удержания фактического размера в рабочей области. Используются только публичные AXSize/AXPosition. Не меняются AXEnhancedUserInterface или системные настройки.
- Перед AX-операцией добавлена пауза 100 ms после активации целевого приложения. Она не включена в диагностическую длительность AX; полная задержка команды больше указанного времени.
- Добавлено имя приложения в picker, bundle identifier в результат и отметка получения shortcut. Названия окон и документов не считываются.
- Исправлен undo: сохранение исходного frame, включая частично заэкранное положение, при неизменном исходном экране. При отключении/изменении геометрии экрана остаётся fallback.
- 10 unit tests прошли, включая два регрессионных случая: исходное заэкранное положение undo и сохранение видимости при отклонённом resize.
- Новая release-сборка успешно собрана, codesign verification прошёл, приложение запущено. UI подтвердил Control+Option+Space. Accessibility=false после изменения ad hoc подписи; Settings открыт для повторного добавления. Реальный результат новой AX-последовательности пока не проверен.

Ориентир для проверки порядка AX-записей: [исходник Rectangle, setFrame](https://github.com/rxhanson/Rectangle/blob/main/Rectangle/AccessibilityElement.swift). В WindowZones не переносится изменение AXEnhancedUserInterface, используемое в этом исходнике.

### Finder: проверка size/position/size без ожидания между записями

Текущий app bundle получил Accessibility. Picker показал «Приложение: Finder», операция записана с `com.apple.finder`. Центральная зона выбрана через кнопку UI-инструментом.

| Операция | Original x/y/w/h | Expected x/y/w/h | Actual x/y/w/h | Результат |
|---|---|---|---|---|
| Центр | 724/57/977/865 | 386/41/740/880 | 724/57/740/871 | adjusted, 137 ms |
| Undo | 724/57/740/871 | 724/57/977/865 | 724/57/788/865 | adjusted, 143 ms |

Ширина наконец изменилась, но позиция осталась исходной. Это согласуется с гипотезой взаимного перезаписывания frame при последовательных AX-вызовах во время анимации, но причина пока не доказана. Undo также не прошёл точное восстановление; расширение за пределы экрана было ограничено Finder.

Следующее изменение: после каждой AX-записи ожидание 150 ms и два чтения frame с интервалом 25 ms. До трёх дополнительных чтений в рамках общего бюджета. Если frame не стабилен, следующая запись не выполняется. Дополнительная запись size только при несовпадении размера; дополнительная запись position только для видимости окна. Каждый промежуточный frame попадает в диагностику, без названий документов. Регулярный snap теперь заведомо может превышать предварительную цель 200 ms; приоритет текущего эксперимента: корректность. Общий бюджет AX не увеличен, медленные/ограниченные окна могут завершаться failed по бюджету. Восстановление после частичной ошибки остаётся best effort.

8 unit tests проходят после изменения, но они проверяют геометрию, не взаимодействие AX с реальным Finder. Реальная проверка новой последовательности ожидается.

### Первый успешный цикл Finder с ожиданием стабилизации

Пользователь выполнил Control+Option+Space и сразу 2. До этого был вызов picker без записи snap; он закрылся до проверки агентом. В тот момент visibleFrame изменился на 1 pt. Отмена по уведомлению экрана/Spaces является гипотезой, причина закрытия не доказана.

| Операция | Original x/y/w/h | Expected x/y/w/h | Actual x/y/w/h | Результат |
