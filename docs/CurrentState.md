# Текущее состояние WindowZones

Обновлено 7 октября 2026. Текущий этап: стабилизация размещения и отмены, карточка [03](tasks/03-stage0-reliability.md). История измерений: [Stage0Results.md](Stage0Results.md). Полный порядок: [NextSteps.md](NextSteps.md).

## Установленная сборка и разработка

Рабочая копия: /Applications/WindowZones.app, локальный кандидат после 0.1.0. Устанавливать только через ./scripts/install.sh --diagnostics. Скрипт тестирует, собирает, подписывает Developer ID команды MW9955TT6R, сохраняет резервную копию и самостоятельно открывает диагностику. Повторные установки с сохранением Accessibility проверены. Не просить пользователя каждый раз открывать приложение. При отказе записи остановить установку и сообщить о необходимом App Management.

Локальный SDK 27.0, минимум macOS 15, arm64. Проверки идут на macOS 27.0.1 (26A434), три дисплея scale 1/2/1. Последний полный прогон: 45 unit tests, release build и проверка подписи прошли. Unit tests не заменяют AX/overlay на Mac.

Резервная релизная копия: .build/backups/WindowZones-0.1.0.app. Резервная копия установки: .build/install-backup/WindowZones.app. Не оставлять в ней сборку с временной инъекцией ошибки после тестирования.

## Изменения после 0.1.0

- b4e9ed6: drag capture разделён на чтение baseline и проверку возможностей. Порог движения 3 pt проверяется до capability checks; защитные фильтры сохранены. Быстрый физический drag после изменения ещё не измерен.
- b4e9ed6: один дополнительный size retry при неточном размере и оставшемся бюджете. Основной бюджет AX 1400 ms, общий с восстановлением 2000 ms. На узкой зоне Slack проверен единственный retry без зацикливания; исправление transient resize Finder именно этой веткой ещё не подтверждено.
- 5a73308: повторяемая подписанная установка. Самостоятельный запуск диагностики и условный reopen не перекрывают уже видимый picker.
- 69b73bf: исправлен порядок rollback между дисплеями. При необходимости сначала уменьшение, затем возврат позиции, затем увеличение и одна ограниченная коррекция позиции. Ошибки показывают этап и конкретный AX-вызов; неподтверждённый actual не заменяется старым замером.

## Что подтверждено на Mac

- В сентябре Finder Retina прошёл 10 последовательных snap/Undo exact. Проверены Tab, Shift+Tab и отмена picker. Это история предыдущей сборки, не текущая полная матрица.
- В октябре на опубликованной 0.1.0 повторно получена нехватка высоты Finder в половинах экрана на 11 и 7 pt; повтор той же команды достигал точного размера.
- На локальном кандидате обычные переносы Finder между основным экраном и Retina, а также Undo давали exact. Контроль после 69b73bf: 498/408 ms. После позднего сбоя и отмены обычная сборка повторно установлена, исходная правая половина основного экрана подтверждена exact за 178 ms.
- Контролируемый сбой после переноса на Retina подтвердил дефект прежнего rollback: высота после возврата 941 вместо 1304 pt. Исправленный код восстановил исходный frame полностью, весь неудачный snap с восстановлением 851 ms.
- Контролируемый поздний сбой при переносе с Retina после увеличения на основном экране: rollback уменьшил окно, вернул на Retina и восстановил исходный frame точно за 1894 ms вместе с операцией. Искусственная ошибка возникала на отметке 1400 ms. Это проверка восстановления, не причина прежнего AX -25204.

- Контролируемая отмена после увеличения на отметке основного deadline не запустила rollback и не обновила Undo. actual оставлен неизвестным, полное время 1463 ms. Это не проверка доставки Space/sleep.

Полные frames, условия, временные тестовые изменения и границы проверок записаны в Stage0Results.md. Контролируемые сбои не должны оставаться в итоговом приложении.

## Что остаётся

1. Причина перемежающегося AX -25204. Теперь диагностика покажет конкретную операцию. Не считать устранённой по успешным snap/Undo.
2. Полная матрица отмены и timeout, реальная доставка Space/sleep, закрытие окна, minimized/fullscreen, отзыв доступа. Проверка состояния перед AX-записью есть, немедленное скрытие picker при изменении отдельного окна не завершено.
3. Пара разных приложений 50/50. У активированного Chrome AXFocusedWindow/noValue, AXMainWindow unavailable и AXWindows count 0. Причина пустого AX-списка ещё неизвестна. Finder/Slack 50/50 измерено точно: оба окна 1268x1304, y=38, gap 8. Slack прошёл 10 циклов snap/Undo exact. Пара Finder/Chrome не проверена.
4. Быстрый drag, Undo после drag, Escape/Shift release, drop вне ячейки, текст/файлы/вкладки/resize, системные края. Пользователь подтвердил первый показ верхней полоски и drop, полная приёмка открыта.
5. Проверки автозапуска с настоящим входом в систему, чистого профиля, повреждённого обновления, сети и удаления. Автозапуск и автоматическая проверка обновлений при предыдущем осмотре выключены.

Управление Terminal запрещено инструментом CUA. Не обходить через другой API или диагностический селектор. Соответствующая автоматическая матрица остаётся непроведённой.
