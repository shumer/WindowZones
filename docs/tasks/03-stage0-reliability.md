## Журнал и следующий шаг

2026-09-19: read-only аудит подтвердил лишнюю отмену по экранным уведомлениям, перехват фокуса на Space и Escape во время capture. Первая ограниченная правка внесена:

- DisplayConfiguration сравнивает экраны по ID. Frame, scale и primaryTop должны совпадать; допустимое отклонение краёв visibleFrame составляет 1 pt к исходному снимку сессии.
- Все проверки picker/drag используют одну политику. Допуск не накапливается между уведомлениями.
- Повторное уведомление не закрывает UI; существенное изменение отменяет. Space/sleep отменяют без активации прежнего приложения и без показа диагностики из catch отменённого AX read.
- Escape отменяет ещё не завершённый capture picker; поздний результат не открывает панель.
- Добавлено 5 регрессионных тестов. Все 15 unit tests прошли. Повторное read-only ревью не нашло новых существенных замечаний в пределах этой правки.
- Release-сборка и проверка подписи прошли. Приложение запущено; Control+Option+Space зарегистрирован, Accessibility=false после пересборки. Открыт Settings, пользовательский шаг выдачи доступа запрошен.
- На текущем запуске обнаружено три экрана, scale 1/2/1. Это позволяет планировать mixed-scale прогон, но пока не подтверждает корректное размещение на них.

Это не завершение карточки. Реальная проверка обновлённого поведения пока не проведена. Unit tests проверяют политику конфигурации, а не доставку системных уведомлений или focus.

### Следующая ручная проверка

1. Проверить Accessibility новой сборки; при сбросе локальной подписи вручную добавить текущий app bundle заново.
2. Finder, Control+Option+Space: picker остаётся открытым без действий, Escape возвращает в исходное приложение.
3. Finder, включить Shift-drag: несколько переносов через зоны без мигания, drop в центр и undo.
4. При открытом picker перейти на другой Space. Picker исчезает, WindowZones не возвращает пользователя назад. Аналогично проверить сон при доступности сценария.
5. Повторить Escape/Shift release. Затем продолжить полную матрицу Stage0.md, не считать этот короткий прогон заменой серий.

Отдельно остаётся lifecycle target: завершение приложения/закрытие окна должно убирать picker, без подмены цели. Текущий AX reference предотвращает выбор другого окна, но немедленное скрытие требует проверки и при необходимости наблюдения за target.

### Продолжение без разрешения AX

Пользователь поручил самостоятельно повторно добавить Accessibility. Нажатие «Добавить» в системных настройках вызвало обязательную аутентификацию Touch ID или паролем. Разрешение не выдано, другие записи не изменялись. Этот шаг требует участия пользователя; обход системной аутентификации не выполнялся.

Пока реальный прогон недоступен, добавлена обработка NSWorkspace.didTerminateApplicationNotification:

- Завершение целевого приложения отменяет активный picker/capture/drag/операцию без возврата фокуса.
- Undo закрытого приложения очищается. Поздний результат AX не восстанавливает его после отмены сессии.
- Завершение постороннего приложения не отменяет текущую сессию.
- Поздние результаты capture дополнительно проверяют, что приложение ещё существует и не завершено.

Правка прошла read-only ревью с исправлением найденной гонки позднего успешного AX-результата. 15 существующих unit tests проходят; они не проверяют доставку NSWorkspace notification. Для этой добавки нужен реальный тест с отдельным тестовым приложением без пользовательских данных и несохранённых документов.

Закрытие отдельного окна при живом приложении, minimized/fullscreen и отзыв AX остаются непроверенными. Обработчик завершения процесса не выдаётся за полное наблюдение за состоянием окна.

Обновлённая release-сборка собрана за 25.68 s, проверка подписи прошла. Прежний процесс WindowZones остановлен для замены bundle; новая версия готова к запуску после системной аутентификации. App bundle: build/WindowZones.app.

### Продолжение: отмена rollback

Во время повторного прогона на macOS 27 проведён read-only аудит target lifecycle. Найдено, что rollback передавал cancellation:nil и мог продолжить AX-записи после отмены по Space/sleep.

В исходниках исправлено: отменённая операция не начинает rollback, перед восстановлением повторяется validate, обе записи и оба settle получают исходный cancellation token. Общий предел start +1.5 сохранён. Debug build прошёл, 42 существующих теста проходят. Эти тесты не проверяют AX cancellation. Независимое ревью фактической правки не нашло блокирующих ошибок.

Правка пока только в исходниках/debug. Release bundle с действующим Accessibility не заменён во время реального прогона. После следующей установки необходим отдельный тест отмены между AX-записями.

Открытые пробелы: picker не скрывается немедленно при закрытии отдельного окна, minimized/fullscreen или отзыве AX; place проверяет состояние перед первой записью, но после await остаются окна гонок. Это следующий ограниченный объём, не завершённая функциональность.

### 2026-10-07: установка и контрольный цикл mixed scale

Две установки через scripts/install.sh прошли с сохранением Accessibility; 45 unit tests прошли. ### 2026-10-07: исправление порядка rollback

Контролируемый сбой после переноса Finder на Retina подтвердил ограничение размера в старом rollback: после возвращения на основной экран высота 941 вместо 1304 pt. Исправленный порядок восстановил frame полностью за 851 ms вместе с неудачным snap. Восстановление сначала при необходимости уменьшает окно, возвращает позицию, затем увеличивает размер. Бюджет 2 s и cancellation сохранены. Добавлены этапы ошибок AX и измерения rollback; устаревший frame не выдаётся за actual после неподтверждённой операции.

Временная инъекция ошибки удалена. Это исправление воспроизведённой ошибки восстановления, не устранение исходного AX -25204. Следующие проверки: поздний timeout/отмена, обратное направление mixed scale, Finder/Chrome и быстрый drag. Подробный протокол в Stage0Results.md.


### 2026-10-07: поздняя ошибка и отмена

Обратное направление проверено на Finder с управляемой ошибкой после увеличения и ожиданием до основного deadline 1400 ms: rollback уменьшил окно на основном экране и вернул исходный frame на Retina, полное время 1894 ms. Во втором опыте отменённый token не запустил rollback, не обновил Undo и не выдал устаревший actual, полное время 1463 ms. Инъекция удалена, код восстановления менять не понадобилось. Подробности в Stage0Results.md.

Это не проверка реального AX timeout, системной доставки Space/sleep или отмены между записями уже начавшегося rollback. Следующий практический шаг: диагностировать Chrome capture AX -25212 и проверить 50/50 с двумя приложениями, затем быстрый drag и оставшийся lifecycle. Этап 0 открыт.

### 2026-10-07: состояние окна при открытом picker

Реализована проверка target каждые 500 ms, без перекрывающихся запросов и без перемещения окна. Собственный token отменяет старый watcher при закрытии панели или новом взаимодействии. Ошибка скрывает picker/overlay без активации target. Через отдельную AppKit fixture на Mac проверены отложенные закрытие отдельного окна и сворачивание, отсутствие Snap, стабильная панель для живого окна, затем placement/Undo. Причины отмены AXRole -25202 и -25204 записаны в Stage0Results.md.

Fixture snap дал adjusted с недостающими 14 pt высоты, Undo exact. Не приписывать этому тесту исправление resize. 45 тестов и подписанная установка прошли. Fullscreen, отзыв доступа, измерение focus/latency и физический drag остаются непроведёнными. Reproducer: Tests/Fixtures/README.md.


### 2026-10-07: стабильность размера после AX

Вместо двух одинаковых выборок через 25 ms требуется 100 ms стабильности относительно одного frame. Общие бюджеты не увеличены. Четыре новых unit tests проверяют короткую паузу, возобновление движения, накопление малых смещений и некорректные входные данные. Все 49 тестов и подписанная установка прошли.

На реальном AppKit Lifecycle Probe пять snap/Undo из (150,558,900,682) в (8,38,1268,1304) и обратно полностью exact. Snap 533-554 ms, Undo 535-589 ms. Ранее в этом сценарии не хватало 14 pt высоты. Это подтверждение на fixture, не всей матрицы приложений. Следом повторить mixed-scale и поздний rollback с новым ожиданием, затем физический drag и оставшийся lifecycle. Полный протокол в Stage0Results.md. Этап 03 не закрыт.
