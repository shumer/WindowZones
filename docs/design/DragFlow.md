# Перетаскивание как основной сценарий

Статус: пользователь согласовал сценарий 19 сентября 2026. Нативная реализация подготовлена, реальная приёмка ещё не завершена. Демонстрация: [DragFlow.html](DragFlow.html).

## Что делает Windows

- Перенос к боковому краю размещает окно на половине экрана, к углу на четверти.
- Перенос вверх показывает Snap bar с раскладками. Выбор происходит во время drag.
- Наведение на кнопку разворачивания и Win+Z дают отдельный выбор раскладки.
- Snap Assist предлагает другие окна для оставшегося места. Такого автоматического заполнения у нас пока нет в объёме.

Источник: [Microsoft, Snap Your Windows](https://support.microsoft.com/en-gb/windows/experience/snap-your-windows), проверен 19 сентября 2026.

## Предлагаемый сценарий WindowZones

1. Пользователь берёт обычное окно за заголовок и начинает двигать его.
2. Только после подтверждения движения самого окна появляется небольшая подсказка у верхнего центра рабочей области.
3. При приближении курсора к подсказке она раскрывается в полоску четырёх раскладок. Мышь всё ещё удерживается, отдельного клика нет.
4. Наведение на ячейку показывает полупрозрачный preview целевой зоны. Остальной экран не перекрывается сеткой.
5. Отпускание мыши над ячейкой размещает исходное окно. Раскладка сохраняется только после успешного AX read-back.
6. Уход из полоски снимает выделение. Отпускание вне ячейки ничего дополнительно не делает. Escape запрещает повторный snap до конца этого жеста.

Shift-drag оставляем как быстрый доступ к зонам уже выбранной раскладки. Панель по shortcut остаётся для клавиатуры и доступности. Меню и диагностика не должны быть обязательным ежедневным маршрутом.

## Сосуществование с macOS

macOS уже размещает окна у краёв и углов. Верхняя строка меню используется для заполнения экрана, движение за верхний край может вызвать Mission Control. Источник: [Apple, Tile windows on Mac](https://support.apple.com/guide/mac-help/tile-app-windows-mchlef287e5d/mac), проверен 19 сентября 2026.

Поэтому кандидат размещения полоски находится ниже строки меню внутри visibleFrame. Это гипотеза, а не доказанное отсутствие конфликта. Системные настройки не менять. При системном изменении размера во время жеста отменять собственный snap. Свою обработку краёв и углов пока не добавлять.

## Реализация по шагам

- [x] Подтвердить направление верхней полоски вместо обязательного выбора отдельной панелью.
- [ ] Отделить подтверждение перемещения от условия Shift в checkDrag. Сохранить отрицательные проверки файлов, текста, вкладок и resize.
- [ ] Проверить быстрый старт drag: сейчас capture отменяется, если за время AX-захвата курсор ушёл больше чем на 3 pt. Это обнаруженное условие в коде, влияние на реальный жест ещё не измерено. Нельзя просто убрать проверку: исходный frame для Undo должен соответствовать началу переноса.
- [ ] Создать чистую модель состояний: idle, tracking, offered, choosing, cancelled. Проверить mouse-up вне ячейки, Escape, смену экрана и поздний AX-ответ.
- [ ] Показать nonactivating panel с ignoresMouseEvents. Попадание в ячейку определять по глобальному курсору; обычные кликабельные кнопки picker для drag не переиспользовать.
- [ ] Передавать layout ID и zone ID в общий путь размещения и сохранения. Undo использует frame до начала жеста.
- [ ] На реальном Mac проверить быстрое и медленное движение, меню-бар, Mission Control, смешанный scale, вырез экрана и отрицательные сценарии.

Прототип HTML иллюстрирует жест внутри условного экрана. Он не управляет окнами macOS и не подтверждает работу AX или системных событий.
