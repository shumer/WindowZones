# Этап 0: проверить реальное управление окнами

Цель: доказать на настоящем Mac, что можно предсказуемо выбрать окно, привязать его к зоне и отменить действие. Это технический прототип, а не макет в браузере.

## Объём

1. Собираемый нативный menu-bar app, отдельное окно диагностики и инструкция сборки. Без full editor, updater и автозапуска.
2. Проверка Accessibility, понятное состояние при отсутствии доступа. Только явные пользовательские команды двигают окна.
3. Три фиксированные зоны 25/50/25 на рабочей области выбранного экрана. Gap и внешний отступ 8 pt. GeometryEngine покрыт unit tests.
4. Захват frontmost window до открытия собственных controls. Команда shortcut + zone picker для отправки этого окна в одну из зон.
5. Read-back фактического frame; отчёт об adjusted/unsupported/denied/failed без зависания интерфейса.
6. Одна операция undo, исходная геометрия сохраняется до команды.
7. После работоспособной команды добавить экспериментальный Shift-drag: detection, overlay, mouse-up snap, Escape, отпускание Shift, undo до начала переноса.
8. Проверить смену монитора и преобразование координат, если второй экран доступен. При недоступности честно отметить, не подменять ручную проверку unit test.

## Эксперименты

| Проверка | Наблюдаемый результат |
|---|---|
| Finder, Safari, Terminal | 10 последовательных snap/undo на приложение без потери target |
| Electron/Chromium из набора пользователя | Минимум два приложения, отдельные результаты |
| Минимальный размер окна | Есть adjusted/unsupported, нет цикла повторных попыток |
| Приложение закрыто между выбором и snap | Нет crash и перемещения другого окна |
| Drag текста / файла / вкладки, resize | Нет ложной активации зон; выполнить не менее 5 попыток каждого типа |
| Escape / отпускание Shift | Snap не происходит после mouse-up |
| Системный tiling включён | Описан конфликт или подтверждено сосуществование на доступной ОС |
| Нет Accessibility / разрешение отозвано | Есть объяснение, интерфейс отвечает |
| Два экрана со смешанным scale | Геометрия верна на обоих или записана воспроизводимая ошибка |

Для AX timeout выбрать начальную границу 250 ms на вызов и общий бюджет операции 1000 ms, затем пересмотреть по измерениям. Не держать UI или event callback заблокированным всё это время. Не обещать поддержку всех приложений по результату одного Safari.

## Что сдать

- Код и воспроизводимую локальную сборку.
- Unit tests геометрии и результаты запуска.
- docs/Stage0Results.md: macOS/SDK/hardware, приложения и версии, конфигурация разрешений, actual/expected frames, ошибки, untested сценарии.
- Доказательство UX: короткое видео или последовательность снимков, если это доступно и пользователь разрешил нужный способ захвата. Отсутствие видео не заменять выдуманным отчётом.
- Решение: идти дальше; поправить способ drag detection; временно ограничить alpha клавиатурой. Отделить подтверждённые ограничения от гипотез.

## Когда этап завершён

Команда размещения и undo работают на трёх базовых приложениях, отрицательные сценарии обработаны, drag эксперимент проведён и его ограничения записаны. Если drag ненадёжен, этап может завершиться обоснованным отрицательным результатом, но цель варианта 3 ещё не достигнута. Не выдавать keyboard-only alpha за готовый FancyZones-аналог.

После отчёта дать пользователю результат проверки и предложенный следующий этап. Не начинать незаметно все остальные этапы.

Уточнение после реального adjusted Undo новой панели: подготовлен основной бюджет 900 ms и общий предел с best-effort rollback 1500 ms. Это верхний бюджет, а не достигнутая latency. Дополнительный проход позиции ограничен одним вызовом после size, без цикла взаимных исправлений. Реальная проверка этой правки ещё не проведена.
