# Контракт ядра раскладок

Модуль Geometry, macOS 15+, текущий Swift 6.4 / SDK 27.0. Это чистый расчёт, без AX, AppKit, файлов или изменения окон. Прототип этапа 0 продолжает пользоваться прежней функцией фиксированных зон.

## Данные

Layout: UUID, имя, root LayoutNode, inset и gap. LayoutNode: leaf с UUID/именем либо split с axis, ratio, first и second. Данные неизменяемые значения. Изменение в редакторе должно создавать новый draft с сохранением ID неизменённых leaf.

Встроенные шаблоны: половины, три колонки, широкий центр, широкий центр с двумя зонами справа. Их UUID постоянны и покрыты тестом контракта. Импорт чужих раскладок не должен получать особое поведение по совпадению с UUID шаблона.

vertical обозначает вертикальный разделитель: first слева, second справа. horizontal обозначает горизонтальный разделитель: first сверху, second снизу. Геометрия возвращается в AppKit y-up; преобразование в AX выполняется отдельно существующим GeometryEngine.flip.

ResolvedZone содержит ID, имя, index с 1 и frame. Номера задаются обходом first, затем second. Они стабильны для одной структуры при смене размеров монитора, но могут измениться после редактирования дерева; постоянным идентификатором остаётся UUID.

## Валидация

- 1-12 leaf, уникальные UUID leaf в пределах раскладки, глубина не больше 12 с root на уровне 1.
- Finite ratio 0.1-0.9 включительно.
- Finite inset/gap 0-32 pt включительно.
- Положительные размеры области и scale, конечные координаты и промежуточные scaled bounds.
- Каждая итоговая сторона leaf не меньше 120 pt после округления.

Слишком маленький экран даёт tooSmall. Дерево не модифицируется, повторный расчёт на большем экране возвращает исходную раскладку. Ошибка не должна превращаться в пустой список с видимостью успешного сохранения.

## Промежутки и пропорции

Внешний inset применяется один раз. Границы рабочей области округляются внутрь: ceil для min, floor для max в backing pixels. Gap округляется до ближайшего backing pixel.

Числовая доля split относится к полезной протяжённости без промежутков. Бюджет промежутков поддерева по оси split вычисляется так:

- leaf: 0;
- разделитель той же оси: собственный gap плюс бюджеты детей;
- перпендикулярный разделитель: максимум бюджетов детей, потому что они делят одну протяжённость по этой оси.

Из размера области вычитаются собственный gap и бюджеты обоих детей. Доля первого ребёнка равна ratio от остатка плюс его бюджет. Второй получает оставшуюся область. Общая граница округляется один раз, соседняя вычисляется через gap. Это исключает накопление щелей из-за независимого округления размеров детей.

Для 1440 pt, inset8, gap8, scale2 широкий центр даёт 352/704/352 pt. Без учёта вложенных gap раньше получилось бы 354/702.5/351.5, поэтому локальная схема вычитания заменена до подключения приложения.

В смешанных деревьях некоторые ветви могут резервировать меньше промежутков, чем максимальный бюджет перпендикулярной ветви. Ratio в этом случае не следует показывать как процент позиции разделителя от полного rect. В редакторе полезная доля и физическое положение преобразуются явно. При добавлении дочернего разделения возможен небольшой сдвиг родительского разделителя при неизменной полезной доле. Это выбранный математический контракт, удобство соответствующего UI ещё нужно проверить.

## Проверки

Геометрические тесты покрывают отрицательные координаты, вложенные splits, отсутствие перекрытий, площадь зон плюс gutters, inward bounds, границу минимального размера, невалидные числа, глубину/количество leaf, стабильность ID и отказ без порчи дерева. Пресеты дополнительно проверяются при gap 0/8/32 и fractional scale. Это не проверка физических мониторов, AX или визуального поведения overlay.
